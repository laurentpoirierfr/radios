# 📻 Radios

Application Android d'écoute de webradios classées par genre (flamenco, jazz, techno, culture…),
pilotée par un fichier de configuration (`config/radios.json`) contenant les
genres, leurs catégories, la liste des radios, leurs flux et leurs logos en base64.

## 2. Proposition de framework : Kotlin + Jetpack Compose + Media3 (ExoPlayer)

### Pourquoi ce choix

Une app de radio internet, c'est d'abord **un lecteur audio robuste en
arrière-plan**. Or c'est précisément le point faible des frameworks
multi-plateformes. Le trio natif Android est la meilleure option :

- **Media3 / ExoPlayer** (bibliothèque officielle Google) : lit nativement les
  flux MP3/AAC progressifs, Icecast/Shoutcast (y compris l'URL en `;`),
  gère les coupures réseau (reconnexion auto), et expose les **métadonnées ICY**
  (titre en cours) pour animer l'interface.
- **`MediaSessionService`** (Media3) : lecture en arrière-plan, notification
  média avec logo de la radio, contrôles casque/Bluetooth/écran verrouillé,
  intégration Android Auto et Assistant — tout est fourni.
- **Jetpack Compose** (Material 3) : UI déclarative moderne, idéale pour une app
  « liste de radios + lecteur ».
- **Coil** : affiche les logos directement depuis les data URI base64 de la
  config (zéro téléchargement au démarrage).
- **APK léger** (~10-15 Mo), pas de runtime supplémentaire embarqué.

### Comparatif avec les alternatives

| Critère | **Kotlin natif** ✅ | Flutter | React Native | Kivy (Python) |
|---|---|---|---|---|
| Lecture de flux MP3/AAC/Icecast | ★★★ ExoPlayer, référence | ★★ `just_audio` correct | ★★ `track-player` | ★ fragile |
| Arrière-plan + notification média | ★★★ `MediaSessionService` | ★★ `audio_service` (réglages fins) | ★★ ponts natifs | ✗ quasi impossible |
| Métadonnées ICY (titre live) | ★★★ | ★★ | ★ | ✗ |
| Multi-plateforme (iOS demain) | ✗ Android seul | ✅✅ | ✅✅ | ✅ théorique |
| Taille / perf de l'app | ★★★ | ★★ | ★★ | ★ |
| Langage à connaître | Kotlin | Dart | TypeScript | Python |

**Recommandation** : partir en **Kotlin natif** pour une app Android de
qualité. Si un portage iOS devient nécessaire *plus tard*, la config
`radios.json` étant indépendante du framework, elle sera réutilisable telle
quelle dans une app Swift/iOS.

### Stack technique proposée

| Brique | Choix | Rôle |
|---|---|---|
| Langage | Kotlin 2.x | — |
| UI | Jetpack Compose + Material 3 | écrans |
| Audio | Media3 ExoPlayer + MediaSessionService | lecture + arrière-plan |
| Images | Coil | logos base64 de la config |
| Sérialisation | kotlinx.serialization | parsing `radios.json` |
| Persistance | DataStore Preferences | favoris, dernière radio écoutée |
| Build | Gradle (Kotlin DSL), AGP 8.x, minSdk 26 | — |

### Architecture cible

```
<racine du dépôt>/                ← racine du projet Gradle (à ouvrir dans Android Studio)
├── settings.gradle.kts, gradlew, gradle/, .run/
├── config/                        ← source de vérité
│   ├── radios.json
│   ├── radios.schema.json
│   └── README.md
└── android/                       ← voir android/README.md
    └── app/src/main/
        ├── assets/radios.json     ← copie du config/ via une tâche Gradle
        └── java/fr/lpoirier/radios/
            ├── data/              ← parsing config + repository (Flow)
            ├── player/            ← RadioPlaybackService (Media3), ICY, reconnexion
            └── ui/                ← écrans Compose (liste, lecteur, favoris)
```

**Écrans prévus (MVP)**

1. **Liste des radios** groupée par catégorie, logos de la config, favoris en tête.
2. **Lecteur** : logo, play/pause, titre en direct (ICY), contrôle du volume.
3. **Favoris / recherche** (DataStore).

**Extensions ensuite** : timer veille, widget d'écran d'accueil, Android Auto,
mode économie de données (bascule vers un flux 64 kbps si la radio en propose).

### Points d'attention techniques

- **TLS incomplet** : `onda-sevilla` et `onda-mencia` n'envoient pas le
  certificat intermédiaire Sectigo → embarquer l'intermédiaire dans l'app
  (trust store par hôte) pour que ces deux flux fonctionnent.
- **`flamenco-fm`** : URL Shoutcast (`;`) — OK avec ExoPlayer, prévoir
  simplement un test de lecture.
- Les flux `zeno.fm` (Deluxe, Plexus) redirigent (302) vers des CDN signés :
  ExoPlayer suit les redirections, rien à faire.
- **Lecture vs téléchargement** : lire le flux via `DefaultHttpDataSource` avec
  `setRequestProperty("Icy-MetaData", "1")` pour recevoir les tags ICY.

### Roadmap

1. ✅ Recensement des radios + flux vérifiés + logos base64 (`config/`)
2. ✅ Squelette Android (Gradle, Compose, copie de la config dans `assets/`) — voir [`android/`](android/README.md)
3. 🟡 MVP : liste + lecture + notification média (codé, à tester sur appareil)
4. 🟡 Favoris, recherche, titre live ICY (codé, à tester sur appareil)
5. ⬜ Timer veille, widget, Android Auto

## Langues et dons

- **Langues** : anglais (par défaut), français, espagnol pour l'interface (`res/values*/strings.xml`).
  Suit la langue du téléphone, ou réglage par app (Android 13+, `res/xml/locales_config.xml`).
  Le contenu de `config/radios.json` (genres, catégories, descriptions, régions) est traduit dans
  `config/i18n/<langue>.json` (voir `config/README.md`).
- **Soutenir l'app** (❤️ en haut à droite) : dons facultatifs via Google Play Billing, produits consommables
  `soutien_cafe`, `soutien_croissant`, `soutien_repas` à créer dans la Play Console (`support/SupportManager.kt`,
  même fichier que dans le projet podcasts).
